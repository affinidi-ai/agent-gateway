# Agent Instructions

This file is the canonical source of truth for project rules, architecture, and
workflow — for both human contributors and AI agents. Agent tools that support the
`AGENTS.md` convention read it automatically. Claude Code reads [`CLAUDE.md`](CLAUDE.md)
instead when both exist, so `CLAUDE.md` imports this file; keep rules, architecture and
commands here. [`CONTEXT.md`](CONTEXT.md) is the terminology
glossary, and [`CONTRIBUTING.md`](CONTRIBUTING.md) covers the contribution workflow
(local checks, tests, and changelog fragments). Source setup and development workflows live in
[`docs/development/GETTING_STARTED.md`](docs/development/GETTING_STARTED.md) and
[`docs/development/DEVELOPMENT.md`](docs/development/DEVELOPMENT.md).

> **MANDATORY before calling any task done: write a changelog fragment.**
> **NEVER edit `CHANGELOG.md` directly.** Instead, create or update `.changelog/wip/<branch>.yaml`.
> Each entry must include `title` and `description`; `title` is a changelog-ready imperative sentence, 80 characters or less, and may keep a leading `⭐` for important changes.
> Read `.git/HEAD` to get the branch name. Replace `/` with `_` for the filename.
> UX changes → `added`/`changed`/`fixed`. Every entry must use a public release category.
> See _Changelog fragments_ below for the exact format.

Project glossary (ubiquitous language) lives in [`CONTEXT.md`](CONTEXT.md). Use it as the source of truth for terminology in code, docs, and Gherkin.

## Rules

1. **Never run any git command which pushes .** Previously caused data loss.
2. **Keep docs in sync with code.** Update relevant docs in the same change as code/config/script changes. Architecture lives in [`ARCHITECTURE.md`](ARCHITECTURE.md) and deep behaviour in the `docs/` implementation references (see [`docs/README.md`](docs/README.md)). Changing policy/egress, MCP tool gating, access tokens/tenancy, or STS means updating `docs/POLICY.md`, `docs/MCP_TOOL_GATING.md`, `docs/ACCESS_TOKENS.md`, or `docs/STS.md`. Use the routing table under _Architecture_ below to find the owning document.
3. **Write a `.changelog/wip/<branch>.yaml` fragment with every change.** NEVER edit `CHANGELOG.md` directly — it is generated by CI. Read `.git/HEAD` for the branch name (replace `/` with `_`). Every entry must use a public release category: `added`/`changed`/`fixed`/`removed`/`security`/`breaking`. Tests, docs, CI, and refactors should be described under the public category that best matches their user-visible effect. Every entry must include `title` and `description`; `title` is a changelog-ready imperative sentence, 80 characters or less, and may keep a leading `⭐` for important changes. See _Changelog fragments_ below for the exact format. **Never skip this step.**
4. **Design work = instruction file updates.** UI/UX/layout/token/component changes MUST update `AGENTS.md` and any local instruction file (`www/default/AGENTS.md` — see _Frontend conventions_ below) in the same change.
5. **No instruction drift.** If live UI disagrees with any instruction file, fix before calling task done.
6. **Avoid overengineering.** Smallest correct change.
7. **No temporary planning artefacts in durable files.** Do not reference AI-generated implementation plans, design notes, rollout phases, PR history, scratch docs, or orphaned requirement labels from source, tests, comments, or long-lived markdown. If context must survive, fold it into stable docs (`AGENTS.md`, `CONTEXT.md`, ADRs, user docs) as current behavior.
8. **No code comments** unless linter-required or genuinely non-obvious. When comments are needed, describe current behavior only — never `PR 1`, `Phase 3`, `AC-1.2.3`, `REQ-3.5.1`, or similar implementation-history breadcrumbs unless they point to a stable checked-in source of truth.
9. **Single Rust binary** (`agent-gateway`), source in `src/`, DashMap cache + filesystem JSON storage, surfaces hot-reloadable. No restart unless modifying startup-only config. Runs in Active or Standby mode (`server_mode` in bootstrap config, default `active`). Health is `GET /api/v1/health` (200 Active-and-ready, 503 Standby); liveness is `GET /api/v1/alive` (always 200); router-relative paths are `/v1/health` and `/v1/alive`. See [`docs/CONFIGURATION_RELOAD.md`](docs/CONFIGURATION_RELOAD.md#server-mode) for the modes and `cache_refresh_interval_secs`.
10. **`AgentSurface`** (`src/config/agent_surface.rs`) is the central routing unit. All proxy behavior hangs off it. Read the surface before touching the pipeline. (Channel-shaped accessors on `AgentSurface`, mirroring the legacy `ChannelMapping` field shapes, live in `src/config/agent_surface_accessors.rs` for mechanical call-site sweeps.)
11. **OPA = Regorus** (Rust-native Rego, no external process). Gateway-level before surface-level.
12. **DashMap is authoritative at runtime.** Disk writes immediate. Manual `_storage/` edits need restart or `POST /v1/config/reload` — unless `cache_refresh_interval_secs` > 0, in which case **DashMap-backed** cached stores pick up external/manual disk writes within that interval (their serialized refresh scans reconcile cache with disk). RwLock-backed stores (policy definitions, global policies) do not poll on this interval and reconcile from disk on restart; explicit configuration reload uses their current in-memory state.
13. **Leave code better** — DRY, no dead code, single-responsibility functions.
14. **Always test** — positive and negative cases.

## Changelog fragments

Every change needs a fragment under `.changelog/wip/<branch>.yaml`. The filename uses the current branch with every `/` replaced by `_` (e.g. `feat/foo` → `.changelog/wip/feat_foo.yaml`), and the `branch:` field keeps the real branch name (with slashes). CI generates `CHANGELOG.md` from these fragments on release — never edit `CHANGELOG.md` directly.

```yaml
branch: <current-git-branch>
changes:
  added: []
  changed:
    - timestamp: '2026-01-01T00:00:00Z'
      title: Describe the user-visible change
      description: Explain what changed and why.
  fixed: []
  removed: []
  security: []
  breaking: []
```
- Put each entry under the public category that best describes the change: `added` / `changed` / `fixed` / `removed` / `security` / `breaking`.
- If a change has no public release effect, leave all category lists empty.
- Every non-empty entry requires an RFC 3339 `timestamp`, a `title`, and a `description`.
- `title` is a changelog-ready imperative sentence, 80 characters or less; important entries may keep a leading `⭐` (counted within the 80).
- `description` says what changed and why — never `Change description`.
- One entry per logical change. Append to the existing branch fragment if one already exists, and commit it alongside the code change.

## Tests

- **Unit**: `#[cfg(test)] mod tests` inline in each module.
- **Behaviour**: the acceptance layer. Gherkin scenarios under `tests/features/surface/` (`surface_bdd`, one gateway) and `tests/features/g2g/` (`g2g_bdd`, two gateways over the fabric). Every new behaviour an operator or caller can observe gets a scenario here; behaviour seen in the dashboard goes to Playwright in `ui-tests/`. After adding or changing a `.feature` file or a step binding, run `python3 scripts/bdd-gherkin.py --lint`; errors block, and CI runs the same check.
  - One behaviour per scenario, in the vocabulary of [`CONTEXT.md`](CONTEXT.md).
  - Exercise the real gateway through its public interfaces.
  - Assert what the caller or operator observes, not internal state.
  - Fixtures store an Access Point as the admin API creates it: closed when it authenticates callers, public when it does not. Test a caller whose credential fails on that protected flow (refused with `401`, the Target never called). Only a scenario about what a public Access Point still guarantees (the failed caller reaches policy, gets no Target credential and no caller identity, and a policy can deny it) says `the surface is stored with a public Access Point`, and only one about a legacy surface says `the surface is stored as a legacy surface`.
- **Legacy component**: `src/component_tests/` is frozen. No new files, test functions or helpers; existing tests may be fixed or deleted. The `freeze` tests in `src/component_tests/mod.rs` pin each file's test count in `FROZEN_FILES` and fail on a new file or a count that moves without its pin. Pins only go down. New helpers are a review rule; the tests do not catch them.
- **MCP conformance**: `make mcp-conformance` (`scripts/mcp-conformance/`) runs the published MCP suite and the legacy compatibility checks against the ordinary gateway binary; `ARGS=--unit-tests` adds the full binary test suite.

## Architecture

[`ARCHITECTURE.md`](ARCHITECTURE.md) is the map: the two planes, the startup sequence,
the inbound, outbound, and fabric paths, the system invariants, and a module map
covering every entry in `src/`. Read it before changing anything on the request path.

Six things are worth knowing before you open it.

**The Agent Surface is the routing unit.** `AgentSurface`
([`src/config/agent_surface.rs`](src/config/agent_surface.rs)) carries one Access Point,
one Target, and zero or more Transit Points. All proxy behaviour hangs off it. Read the
surface before touching the pipeline. Channel-shaped accessors mirroring the legacy
`ChannelMapping` field shapes live in
[`src/config/agent_surface_accessors.rs`](src/config/agent_surface_accessors.rs).

**Gateway policy runs before surface policy, and a gateway deny is final.** There are
exactly two planes. The package name is load-bearing, and the wrong package fails
closed.

| Scope   | Package                  | Query                       |
| ------- | ------------------------ | --------------------------- |
| Gateway | `package gateway.policy` | `data.gateway.policy.allow` |
| Surface | `package surface.policy` | `data.surface.policy.allow` |

Legacy `package channel.policy` is migrated to `surface.policy` at boot. Deny reasons
are `data.gateway.policy.deny_reason` and `data.surface.policy.deny_reason`.

**Policy planes and identity attribution fail closed.** Two stages publish results and
let OPA decide instead: Trust Check, and caller source authentication. Source authentication
hands a failed caller to policy only on a public Access Point (`access_point.public: true`);
every other Access Point refuses it before policy with a `401`, direct or over Fabric: a closed
one (`public: false`), a legacy one stored without `public`, and any whose
`caller_authentication.on_failure` is `reject`. Two more refuse it, public or not: an Access
Point whose inbound identity is `from_jwt_claim` (no caller identity can be derived without a
valid JWT), and an MCP Access Point that publishes protected resource metadata (a missing or
refused JWT Bearer credential gets the discovery challenge on direct requests, a failed
credential of another method a plain `401`). Each such refusal's body says only `Caller
credential missing or invalid`; the reason is logged, not sent. The admin API creates every
surface closed unless `access_point.public` is `true`; a closed surface without source
authentication is not ready and refuses every request with `503`. A legacy surface without
source authentication admits every caller. On a public Access Point, policy must deny
`input.source_auth.method == "failed"` to reject failed callers.
See [`docs/SOURCE_AUTH.md`](docs/SOURCE_AUTH.md#closed-and-public-access-points) and
[`docs/POLICY.md`](docs/POLICY.md#failed-caller-authentication).

**MCP revisions are admitted per transport path.** Every MCP endpoint admits `2026-07-28`
alongside the session revisions listed in [`docs/MCP_METADATA.md`](docs/MCP_METADATA.md#modern-mcp-admission).
Session revisions are forwarded to the upstream, except that gateway-owned MCP Proxies answer
`initialize` themselves with `2024-11-05`. Resolve versions through `runtime_policy_for` /
`admission_policy_for_target` ([`src/mcp/request_validation.rs`](src/mcp/request_validation.rs)),
never an appliance-wide constant. See [`docs/MCP_METADATA.md`](docs/MCP_METADATA.md).

**A2A versions and message validation are set per surface.** An A2A Access Point's
`access_point.a2a` lists its accepted versions (`0.3` and `1.0` by default) and its
`validation` level: `off`, `envelope` (the JSON-RPC envelope, the default) or `full` (also the
A2A request shape). An `a2a-proxy://` surface's versions are fixed (`1.0` only when new; existing ones keep theirs), and it always checks `envelope`. Read them through `AgentSurface::a2a_settings`
([`src/config/agent_surface.rs`](src/config/agent_surface.rs)), never a global flag. See
[`docs/PROTOCOLS.md`](docs/PROTOCOLS.md#a2a-surface-settings).

**Payment is delegated to agent-pay.** A surface charges only through an `agent_pay`
payment policy that names a payment surface on a connected payment gateway: a remote gateway
record with `role: payment`, managed under `/v1/payment-gateways/*` and `payment_gateways.*`
while `/v1/gateways/*` serves peers only ([`src/gateways/role_scope.rs`](src/gateways/role_scope.rs));
a payment gateway is never a `fabric://` route. An enabled local
x402 or MPP policy still loads but is unsupported: the surface answers `503
payment_unavailable` and the policy cannot be saved. Read it through
`AgentSurface::agent_pay_policy` / `payment_policy_unsupported`
([`src/config/agent_surface_accessors.rs`](src/config/agent_surface_accessors.rs)). This
gateway decides whether a request is chargeable and agent-pay takes the payment, only after
policy and just before forwarding, on every path (direct, `fabric://` Target, MCP and A2A
proxy Targets, Fabric receive); a free request makes no fabric hop. The gate lives in
[`src/proxy/handler/agent_pay_gate.rs`](src/proxy/handler/agent_pay_gate.rs). This gateway
captures funds agent-pay only held (`payment-authorization`) once the Target delivered and voids
them otherwise, recording the decision in the payments ledger first
([`src/payments_ledger/settlement.rs`](src/payments_ledger/settlement.rs)); a streamed response
is captured once a result is passed on, or settled when its stream ends ([`src/proxy/handler/agent_pay_gate/streamed.rs`](src/proxy/handler/agent_pay_gate/streamed.rs)),
and callers poll held cases through
[`src/payments_ledger/caller_api.rs`](src/payments_ledger/caller_api.rs). The gateway-signed
payment credentials (receipt, rejection, access grant) are dispute evidence that nothing accepts
as proof of access; their JWT stays in the local VP Audit Log and only the fingerprint leaves it
(integrations, admin API). This gateway
is not an x402 facilitator: a peer's fabric `x402/verify-request` or `x402/settle-request` is
refused with `facilitator_disabled`, whatever `facilitator_mode` says. See
[`docs/CONFIGURATION_REFERENCE.md`](docs/CONFIGURATION_REFERENCE.md#surface-payment-policy).

# Ways of working

## New features

1. Clarify requirements first — one question at a time. Capture durable decisions in stable repo docs only when they truly belong there.
2. Design interfaces/structure before code.
3. Prepare Gherkin scenarios for each observable feature behaviour.
4. Incremental steps, each test-first: write the unit test, watch it fail for the reason the step exists, then make it pass. A test that was never red proves nothing.
5. Keep stable docs in sync, but do not treat temporary implementation or design plans as source of truth.
6. Unit tests must assert returned values, not just no-error.

## Commands to run

1. compile check: `cargo test --no-run 2>&1 | grep -E "^error\[E|^warning|^\s*-->|Finished"`
2. module tests: `cargo test --bin agent-gateway "<module name>"`

`make test`, `make ui-test` and the other test targets depend on `config-test`, which prepares
the certificates and keys the tests need. Run `make config-test` once before invoking `cargo test`
directly.

`make help` lists every target. The ones used most:

| Task                                                    | Command                                            |
| ------------------------------------------------------- | -------------------------------------------------- |
| Fast compile check                                      | `make check`                                       |
| Build backend and frontend                              | `make dev`                                         |
| Run locally (builds www + cargo)                        | `make run-debug` (`x=<name>` for a named instance) |
| All Rust tests                                          | `make test` (`test=<name>` filters)                |
| Frontend unit tests                                     | `make npm-test`                                    |
| Playwright UI tests                                     | `make ui-test`                                     |
| Lint everything (fmt check, Clippy, ESLint, ShellCheck) | `make lint`                                        |
| Format Rust and frontend                                | `make fmt`                                         |
| Local CI preflight                                      | `make ci`                                          |
| MCP conformance                                         | `make mcp-conformance`                             |

## Before ready for review

1. `cargo clippy --all-targets --all-features` — fix all warnings/errors
2. `cargo fmt --all`
3. `cargo test --no-fail-fast --all-targets --all-features`
4. If `www/default/` files changed: `cd www/default && npx prettier --write src && npm run lint`
5. If MCP admission, forwarding or owned dispatch changed: `make mcp-conformance`
6. If `tests/features/` or a step binding changed: `python3 scripts/bdd-gherkin.py --lint`
